# v1.0

Goal: CI-grade. Test-granularity routing, incremental mode, full reporting.

## Features

- Tracer coverage routing at test granularity: covering tests only, fastest
  first, first-kill-wins (v0.1 routes at suite granularity)
- Incremental `--diff-base <ref>` at line granularity
- `flutter test` support
- Full syntax-coverage metric in reports
- Bundled HTML report
- LLM-optimized Markdown report (per-survivor "missing test" hints)
- CI dogfooding: a scheduled workflow runs `rad` on this package and gates on
  `--threshold` and `--max-timeouts`

## Design guidance for later stages

- Record per-mutant timing and kill-test identity: inputs for v2.0 history
  files and dashboard baselines.
- Survivor records carry span + replacement + diff: enough for v2.0
  `dart analyze` checks and PR annotations without re-running.
- Report sinks are additive; new formats must not change the run pipeline.
- Stretch: deterministic full-suite load calibration for worker-count tuning.

## Dogfooding in CI

- Suite routing (v0.1) brought a self-run to ~1.7 h
  ([../plans/self-run-performance.md](../plans/self-run-performance.md)):
  schedulable, still far past a pull request's patience until `--diff-base`.
- Own workflow, not the CI or publish one, so a slow self-run never gates a
  merge or a release.
- Scheduled plus manual dispatch first; `--diff-base` makes per-PR runs
  affordable once incremental mode ships.
- One run lock per machine ([ADR 0018](../decisions/0018-run-workspace-lifecycle.md)):
  the workflow needs its own runner or a serialized concurrency group.
- Upload the Stryker JSON as an artifact; the threshold gate is the signal,
  the report is the evidence.
- Nested runs: the self-run's suite spawns `rad`, so containment paths and
  logs must stay isolated per invocation.
